### 猫岛胜景 v2:从低模 PBR 升到赛璐璐渲染(2026-11-24)

上一条留的"结构性差距"(低模平涂 vs 动画质感、树冠偏尖锥、没有色彩分级)这次正面处理了。
做法是**在引擎层集中升级,12 个模块的接口一行没改**:

| 层 | v1 | v2 |
|---|---|---|
| 着色 | PBR 光滑明暗 | `post.js` 在模块装载后遍历场景,给全部 `MeshStandardMaterial` 注入三阶色阶 + 边缘光(64 个材质一次搞定) |
| 描边 | 无 | 渲染前用「法线材质」再画一遍场景,合成时做深度 + 法线边缘检测 → 墨线;精灵和"半透明/双面的 Basic 材质"自动跳过 |
| 光影 | 只有假阴影片 | 高画质档开实时投影(阴影已折进直接光颜色,所以阴影边与色阶边天然一致);假阴影片保留给中/低档 |
| 天空 | 渐变贴图球 + 7 朵面片云 | 单个着色器:三段霞色、日轮 + 光晕写进 HDR、投影到高空平面的 fbm 积云(亮部朝太阳方向偏移采样出体积感) |
| 海面 | 平面 + 3 层滚动贴图 + 2 圈泡沫环 | 着色器:由 `heightAt` 烘"岸线距离场"(两遍倒角距离变换)→ 浅滩青绿到深海蓝紫、缠岸泡沫、噪声等值线浪线、菲涅尔、太阳碎金 |
| 后期 | 无 | HDR(MSAA×4)→ 提亮 + 两轮可分离模糊 → 合成(描边、饱和、S 曲线、暗角、颗粒)→ ACES |
| 内容 | 清一色尖锥松 | 阔叶(6 团多面体球,底暗顶亮)+ 松的混交林;崖壁蓝紫底 + 玫瑰色细地层;草色提亮;低空雾片减到约 1/3 |

**三档画质实测(1280×720,本机)**:高 ≈630 draw calls / 22.6 万三角面 / 11.3ms;中 ≈190 / 5.8 万 / 2.9ms;低 ≈145 / 5.2 万 / 1.6ms。
高档把场景画三遍(预通道、阴影、主画面),是中档的约 3 倍;既有的"帧率自动降档"会把弱核显落到中档,而中档比 v1 还轻。

**这一轮踩的坑(都已写进 AGENTS.md / CONTRACT.md)**:
1. `onBeforeCompile` 拿到的着色器里 `#include` **还没展开**。我按函数名去搜 `RE_Direct_Physical` 搜不到,补丁静默失效,却一度以为卡通着色已生效(看到的其实是平直着色)。
2. uniform 挂进了 `shader.uniforms`,GLSL 里却没写声明 → 全部材质编译失败 → 物体消失、只剩描边浮在背景上。
   three 的着色器编译错误**只打控制台、不抛异常**,而我之前的"零报错"检查恰好是在补丁还是空操作时做的。
   现在测试工具每次出图都读 `renderer.info.programs.filter(p => p.diagnostics).length`。
3. 自定义 `ShaderMaterial` 开 `fog: true` 必须合并 `UniformsLib.fog`;片元末尾必须有 `tonemapping_fragment` + `colorspace_fragment`,
   否则低画质直出时天空海面是另一套生猛的配色。
4. **测试环境污染结论**:`python -m http.server` 不发缓存头,Chrome 给"很久没改过的模块"判了约 12 小时的缓存新鲜期,
   我改了 `water.js` 两次,页面跑的一直是旧模块,还以为是着色器参数不对。已新增 `tools/serve.py`(no-store)。
5. 海面是 1300² 的方块:从某些角度能看到方块的直边,与"地平线以下的天空"颜色不同就成了海平线上的一条暗线。
   海面放大到 3000²、穹顶 1100、地平线以下色 = 雾色,三件事一起才消掉。

6. **靠印象判断画面会跑偏**:收尾阶段我一度认定"线上比本地灰""细波把菲涅尔污染了",追了半天;
   用像素统计和逐张差分一量,本地的几张"定稿"其实是同一张(平均差 2.4/255),
   线上受控取样与本地也只差 0.1。真正的异常只有部署刚完成那一刻的一张(近海偏红 +25),再没复现。
   教训:**改画面前后用同一机位、同一时刻、同一条代码路径背靠背取样,做差分和分区统计,不以肉眼印象为准**。
   (细波排除在菲涅尔之外的改动保留:原理上正确,但它不是在修一个已观察到的问题。)

**这一轮新踩的坑**

1. **按材质过滤场景时把"没有材质"当成了跳过**。Scene、Group、灯光都没有 `material`,
   描边预通道把整个场景连子节点一起藏掉,画出一张空图——症状是"描边完全不出现",不报错。
   我先怀疑着色器、怀疑纹理绑定,手动跑预通道读回像素才定位到被藏掉的 115 个对象里有 `Scene`。
   猫岛当时没踩到,只是因为那边的规则恰好只判断了"有材质且属于某类型"。
2. **合集守卫写成 `window.Nikki`**。`common.js` 里 `Nikki` 是顶层 `const`(词法绑定),不是 window 的属性,
   游戏启动时判断为"独立运行",收了鱼不发金币。实测才暴露。
3. **`Color` 被转了两次线性空间**。r160 开着色彩管理,`new Color('#hex')` 已经是线性的,
   旧代码又调 `convertSRGBToLinear()`——顶点色的地形 / 植被比设计值又暗又脏,而 uniform 上色的鹈鹕是正常的,
   两套颜色的"对不上"一直藏在画面里。改成只转一次后,又反过来发现受光面被叠到了 1.5 倍固有色,
   亮色全部漂白(第一次重载的截图"像蒙了一层粉")→ 把白天光强压回受光面 ≈ 固有色。
4. **阴影的 `normalBias` 是 0.6 米**,比车架和辐条还粗,细物体的影子被整个推没。
5. **测试工具自身的坑**:在 `await` 之后才 `toDataURL` → 绘图缓冲已清空,六张全黑;
   `scrollIntoView` 撞上 `scroll-behavior: smooth`,坐标取早了;嵌入式浏览器的后台标签页
   **收不到真实指针输入**(定位器点击超时、坐标点击无效),"用真实鼠标操作每个控件"这一条在这里做不了,
   只能用脚本触发 + 审计截图核对,如实记为未完成。
6. 卡丁车内部渲染缓冲只有 330×165,渲染器又是模块内部变量:抓封面时在 GL 层手动设视口,
   而 three 缓存了视口状态、认为没变就不再下发,第一张图只在左下角渲染了一小块。

**仍然不满意 / 等模型能力升级后再做的**

- **几何还是"基元拼搭"**:鹈鹕是球 + 圆锥,小屋是盒子,车是圆柱。渲染层(着色、描边、天空、光)已经到位,
  但模型本身没有"造型设计"。真正再上一个台阶需要能生成或手写出有体积转折的模型(或出图后描模)。
- **内容密度不均**:草坡大片是同一色 + 中频斑驳,村庄之外的地标间距很大;动物只有海鸥、蝴蝶、萤火虫。
- **草丛与花没有描边**(薄片描了会糊成黑块),近看和带墨线的树不是一个笔触。
- **没有在真实 GPU 上量过帧率**:嵌入式浏览器里 `gl.finish` 不等 GPU(测出来 1.2ms,不可信),
  只知道高档一帧 ≈386 次绘制 / 205 万三角面(描边预通道占 139 次 / 62 万面),靠自动降档兜底。
- **触屏按键只验证了会显示、会写键位**,没在真机上骑过。
- **主页的插画封面是我手写的符号化图形**(每个 8~15 个形状),风格统一,但离"游戏 Key Art"很远;
  2D 游戏也没有真实截图当封面(需要逐个游戏做确定性取帧)。出图模型当时是 403,恢复后优先换掉这批。
